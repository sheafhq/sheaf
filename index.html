01 / The problem

The dispute is no longer “did the transaction complete?”

It is “was the agent actually authorized to act for this payer?” The merchant holds the checkout session, the order record, and the agent logs. The issuer has no independent reason to trust any of them. Logs can be edited. Sessions can be replayed. Screenshots prove nothing.

~2.4×agent-initiated card dispute rate vs. comparable human CNP
~76%of those disputes are friendly fraud
22% → 68%measured representment lift with signed, machine-readable evidence
02 / The solution

A portable evidence bundle, not a dashboard row.

A .sheaf Dispute Bundle binds the authorization claim to the execution record and anchors it on Base L2. The issuer’s analyst can verify it offline with a pinned key and any Base RPC. No Sheaf server. No trust in the merchant’s mutable logs.

01 / MANDATE

What the agent could do

Merchant, tools, amount ceiling, validity window, named principal.

02 / DELEGATION

Who authorized the agent

Chain of authority back to a human or policy, with parent refs.

03 / CONSENT

That the payer agreed

Hash-bound payer authorization, timestamped before execution.

04 / EXECUTION

What actually happened

Signed, hash-chained tool calls with payload hashes and Merkle inclusion proofs.
